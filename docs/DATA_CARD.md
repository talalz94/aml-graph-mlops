## What is in it

Six independent datasets: HI (higher laundering rate) and LI (lower), each in small, medium and large. This repo starts with HI-Small:

| | HI-Small (from the Kaggle page) |
|---|---|
| Period | 1 to 10 September 2022 |
| Bank accounts | 515K |
| Transactions | 5M |
| Laundering transactions | 5.1K (1 in 981) |

Each dataset has a transactions file (timestamp, sending bank and account, receiving bank and account, amounts and currencies, payment format, laundering label) and a patterns file listing laundering attempts that follow one of eight typologies (fan out, fan in, cycle, gather scatter, scatter gather, stack, random, bipartite). Not all laundering follows a listed pattern.

## Processing

- The transaction file's header repeats the name "Account", so files are read with fixed column names and the header line is skipped.
- **Late transactions are dropped.** Transactions after the main period are all laundering (pointed out in the Kaggle discussion), so keeping them would let a model learn the label from the date. For HI-Small, transactions from 11 September 2022 on are removed.
- **Amounts in US Dollar.** Amounts come in many currencies, so paid and received amounts are converted before anything is summed. Each currency's rate on a day is the median US Dollar rate over the rows that pair it with US Dollar on or before that day, and 1.0 until such a row exists.
- **Self transfers** (an account paying itself) move no money between accounts. They are left out of the account totals, the pair counts and the 2 cycle check, and the rules never alert on them; the `self_loop` feature marks them.
- **Split by time:** 60/20/20 train, dev, test in whole calendar days, with the two cut days chosen by the rule in IBM's Multi-GNN code (the pair of days whose worst relative miss on the three shares is smallest). The paper's test split also holds the late transactions this repo drops, so the two test sets differ, and the published F1 figures in the README are a rough guide, not a like for like comparison.
- **Features never use a later day or any label.** `tests/test_features.py` checks this on generated data: cutting the file after each of its days leaves the features of every transaction up to that day unchanged, and shuffling the labels across rows changes no feature.

## Known limits

- It is synthetic. Real laundering is rarer, more varied and less completely labelled.
- One simulated world: a model tuned here can lean on quirks of the generator.
- The patterns file covers only part of the laundering, so per pattern recall is a partial view.

## Generated test data

`aml synth` writes a small dataset in the same layout with planted fan out, fan in, cycle and scatter gather patterns, some payments that change currency at fixed rates, and some payments from an account to itself. It exists for tests, CI and the Quickstart demo (`uv run poe demo`). Numbers from it are never reported: its scores go to `data/results/` unless you pass `--results-dir`, `aml report` never renders them, and git ignores `results/SYN/`.
